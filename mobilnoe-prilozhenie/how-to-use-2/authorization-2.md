### Первый вход в приложение {#firstentry}

Работать в мобильном приложении могут только авторизованные пользователи.

#### Выполнение действия

- Первый экран входа в приложение

    Введите адрес сервера, на котором развернуто приложение и нажмите **Далее**.

    Правила заполнения адреса сервера:
    - **Префикс протокола http** — префикс можно не указывать, он добавится автоматически.

        Пример, naumen-sd.ru → http://naumen-sd.ru.
    - **Префикс протокола https** — префикс можно не указывать, он добавится автоматически. Должен быть доверенный сертификат.

        Примеры, naumen-sd.ru → https://naumen-sd.ru, http//naumen-sd.ru → https://naumen-sd.ru.
    - **Постфикс** — постфикс "/sd" в адресе можно не указывать, он добавится автоматически.

        Примеры, naumen-sd.ru → http://naumen-sd.ru/sd/, http://naumen-sd.ru → http://naumen-sd.ru/sd/, http//naumen-sd.ru/sd → https://naumen-sd.ru/sd/.
    - **Наклонная черта** — наклонная черта в конце адресной строки добавляется автоматически при необходимости.

        Пример, http://naumen-sd.ru/sd → http://naumen-sd.ru/sd/.
    - **Порт** — порт 80 (по умолчанию).

        Другой порт необходимо явно указать в строке адреса.

        Пример, http://naumen-sd.ru:8080/sd.
    - **Редирект** — редиректы не поддерживаются.
- Второй экран входа в приложение

    Укажите логин и пароль пользователя и нажмите **Начать работу**.

    На экране отображается сообщение со ссылкой на политику конфиденциальности компании. По ссылке выполняется переход на сайт компании NAUMEN и отображается полная версия политики конфиденциальности.

    <image src="./authorization_A_2_15.png" alt="Второй экран входа для 15.0" scale="17.7"/>

<note type="info">

Содержание второго экрана входа зависит от выбранного типа аутентификации в мобильном приложении (аутентификация может осуществляться через внешний сервис, например, Azure AD). Логотип на экране входа соответствует логотипу, установленному для темы интерфейса оператора, которая выбрана пользователем в веб-интерфейсе или задана по умолчанию.

</note>

#### Результат входа в систему

При успешной аутентификации пользователя на экране отобразится первый доступный для просмотра экран: список объектов, карточка объекта, встроенное приложение. Если нет экранов, доступных для просмотра, то отобразится сообщение "Нет доступных списков или карточек" и **Обновить**.

При успешной авторизации в мобильном приложении автоматически создается аккаунт с параметрами, указанными при авторизации. Подробное описание аккаунтов приведено в разделе [Аккаунты. Android](./navigation-2/settings-2/accounts-2).

### Первый вход в приложение по ссылке с адресом сервера {#firstentry_link}

Работать в мобильном приложении могут только авторизованные пользователи.

#### Выполнение действия

- При открытии ссылки в мобильном приложении адрес сервера заполняется автоматически и выполняется переход на второй экран входа.

    Если попытка перейти на второй экран входа по короткому адресу (без протокола взаимодействия и суффикса /sd) оказалась неудачной, то введите полный адрес сервера.
- На втором экране входа укажите логин и пароль пользователя и нажмите  **Начать работу**.

    Ссылка на приложение может содержать логин пользователя, в этом случае поле логина заполняется автоматически. Для формирования ссылки используются скриптовые методы, см. [Скриптовые методы](../how-to-setup/from-web/scripts).

    На экране отображается сообщение со ссылкой на политику конфиденциальности компании. По ссылке выполняется переход на сайт компании NAUMEN и отображается полная версия политики конфиденциальности.

#### Результат входа в систему

При успешной аутентификации пользователя на экране отобразится первый доступный для просмотра экран: список объектов, карточка объекта, встроенное приложение. Если нет экранов, доступных для просмотра, то отобразится сообщение "Нет доступных списков или карточек" и **Обновить**.

При успешной авторизации в мобильном приложении автоматически создается аккаунт с параметрами, указанными при авторизации. Подробное описание аккаунтов приведено в разделе [Аккаунты. iOS](../how-to-use/navigation/settings/accounts).

### Повторный вход {#reentry}

При повторном входе в приложение (если не настроена дополнительная аутентификация) происходит автоматическая авторизация пользователя и выполняется вход в приложение.

При успешной аутентификации пользователя на экране отобразится первый доступный для просмотра экран: список объектов, карточка объекта, встроенное приложение. Если нет экранов, доступных для просмотра, то отобразится сообщение "Нет доступных списков или карточек" и **Обновить**.

### Повторный вход с дополнительной аутентификацией {#reentry_bio}

При повторном входе в приложение после блокировки экрана телефона или выгрузки приложения из оперативной памяти устройства открывается экран входа по ПИН-коду или биометрическим данным.

<note type="info">

Настройка дополнительной аутентификации описана в разделе [Настройка дополнительной аутентификации в мобильном приложении](../how-to-use/navigation/settings/app-settings#04).

</note>

#### Выполнение действия

Для входа в мобильное приложение введите ПИН-код или биометрические данные.

#### Результат входа в систему

При успешной аутентификации пользователя на экране отобразится первый доступный для просмотра экран: список объектов, карточка объекта, встроенное приложение. Если нет экранов, доступных для просмотра, то отобразится сообщение "Нет доступных списков или карточек" и **Обновить**.

#### Сброс ПИН-кода

При попытке ввода неверного ПИН-кода на экране отображается счетчик неудачных попыток ввода ПИН-кода, если количество неудачных попыток ввода задано в настройках. После успешной аутентификации по ПИН-коду или биометрическим данным счетчик попыток восстанавливается. Если попытки закончились, то ПИН-код сбрасывается.

При сбросе ПИН-кода удаляются все данные приложения, кроме адреса сервера последнего активного аккаунта и очереди синхронизации.

После сброса ПИН-кода для входа в мобильное приложение потребуется ввод логина и пароля.

### Причины ошибок при входе в мобильное приложение {#error}

- по указанному адресу система не найдена;
- модуль "Мобильное приложение" выключен, отсутствует или у него истек срок лицензии;
- введенные логин и пароль не корректны;
- введенный пароль является устаревшим в результате принудительной смены пароля или истечения времени действия пароля;
- пользователь заходит без сертификата или с истекшим TLS-сертификатом;
- пользователь заблокирован;
- пользователь находится в архиве;
- на устройстве установлена неактуальная версия сервисов Google Play.

<note type="info">

Если сервисы Google Play не установлены, то предлагается обновить сервисы или перейти на версию мобильного приложения без уведомлений. Пользователь может установит флажок "Больше не показывать" и при повторном входе в систему сразу будет выполняться переход к версии без уведомлений. 
Отличие версии мобильного приложения без уведомлений: Сервер не отправляет пуш-уведомления на мобильное устройство. Нельзя использовать режим запроса текущего местоположения для инженера при использовании встроенного приложения "Карта". Геоданные сотрудника будут отправляться на сервер только в режиме отслеживания перемещений.

</note>
